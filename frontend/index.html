EVE-NG · the running lab and SSH access

See this lab in the EVE-NG web page
  1. The dashboard controls the routers as the EVE account bgpapi (pod 1). A pod is a separate space in EVE-NG, so an account in another pod, such as admin (pod -1), never sees these routers running.
  2. Create a second EVE account for the web page, once: System → User management → Add new user, role Administrator, POD 1, expiration -1, a password you choose.
  3. Log in to EVE-NG with that account and open the lab from the folder list (the path above). The routers show as running. Reach them by SSH with the commands below, not through the EVE-NG telnet console.
  4. Use a separate account for the web page: EVE-NG keeps one session per account, so using bgpapi itself would log you out whenever the dashboard talks to EVE-NG.
Open routers in PuTTY (one-time setup on your PC)
  1. The SSH session button starts a separate PuTTY window for that router. A web page cannot start programs, so your PC needs a small link handler, set up once: in the repository folder run powershell -ExecutionPolicy Bypass -File scripts\putty-setup.ps1. It adds one saved PuTTY session per router (named BGP <lab> <router>) and a bgpputty: link, for your Windows user only. -DryRun shows what it would do, -Uninstall removes it.
  2. The first click makes the browser ask whether to open PuTTY links: allow it (and tick "always allow").
  3. PuTTY connects through the EVE-NG VM with the Windows OpenSSH key you already use for the VM, then asks for the password of user lab: see the Credentials tab. Type enable for privileged mode.
